# Pipeline Architecture

> Pure `.lua` (Hyprland v0.55+). Verified against actual code in
> [`bootstrap/default.lua`](../../bootstrap/default.lua) and
> [`sys/default.lua`](../../sys/default.lua).

## Overview

The config is a **pipeline of `require()` calls** that runs top-to-bottom at
Hyprland startup (and on every reload). Each module mutates shared state:

- `const` module — constants (injected by Stage 0 via `package.loaded["const"] = const`)
- Hyprland internal state — via `hl.config()`, `hl.bind()`, `hl.window_rule()`, etc.

**require order = override priority**: later modules win (last-write-wins).

## Compiler Pipeline Analogy

| Compiler phase | Lua interpretation | Where |
| --- | --- | --- |
| Lexical | `require()` resolves module paths via `package.path` | All files |
| Syntax | `require()` DAG executes in order: `bootstrap.default` → `sys.default` → `sys.X` + `user.X` | `bootstrap/default.lua`, `sys/default.lua` |
| Semantic | `hl.window_rule({ match = { tag = "X" } })` validated against tag registry | `sys/rules.lua` references tags from `sys/tags.lua` |
| Codegen | `hl.config({...})` calls mutate Hyprland's internal C++ state | `sys/decoration.lua`, `sys/input.lua`, etc. |
| JIT | `hl.bind(key, fn)` runtime dispatch + `hl.on(event, fn)` reactive hooks | `sys/keybind.lua`, `sys/startup.lua` |

## Complete Pipeline (verified)

```
hyprland.lua                              ← entry point (6 lines)
  └── require("bootstrap.default")
        │
        ├── Stage 0: const layers (build merged `const` module + inject via package.loaded)
        │   ├── require("bootstrap.const")     ← Layer 1: paths (immutable)
        │   ├── require("sys.const")            ← Layer 2: system defaults
        │   └── require("user.const")           ← Layer 3: user deltas (WINS)
        │
        └── Stage 1+: require("sys.default")
              │
              ├── require("sys.hardware.default")
              │     ├── sys/hardware/laptop.lua       ← media keys, touchpad
              │     ├── sys/hardware/monitors.lua     ← monitor layout
              │     └── sys/hardware/workspaces.lua   ← workspace bindings
              │
              ├── require("sys.policy.default")
              │     ├── sys/policy/wallust/wallust-hyprland.lua   ← generated colors
              │     └── sys/policy/animations/default.lua          ← animation preset
              │
              ├── require("sys.env")     →  require("user.env")        ← hl.env() calls
              ├── require("sys.misc")    →  require("user.misc")       ← hl.config({ misc = ... })
              ├── require("sys.input")   →  require("user.input")      ← kb_layout, follow_mouse
              ├── require("sys.layout")  →  require("user.layout")    ← layout engine
              ├── require("sys.decoration") → require("user.decoration") ← blur, shadows, rounding
              ├── require("sys.render")  →  require("user.render")    ← direct_scanout, vfr
              ├── require("sys.startup") →  require("user.startup")   ← hl.on("hyprland.start", fn)
              ├── require("sys.keybind") →  require("user.keybind")   ← hl.bind() calls (132 binds)
              ├── require("sys.tags")     →  require("user.tags")      ← hl.window_rule({ tag = ... })
              └── require("sys.rules")    →  require("user.rules")    ← hl.window_rule({ effects... })
```

## Stage 0: Constants Pipeline

**Purpose**: Build and register the merged `const` module (single source of truth) before any module reads it.

**Order** (`deep_merge()` overlays user deltas on sys defaults):
1. `bootstrap/const.lua` — path infrastructure (`config_hypr`, `sys`, `user`)
2. `sys/const.lua` — system defaults (`apps`, `modifier`, `dirs`, `external`, ...)
3. `user/const.lua` — user deltas (overrides)
4. `bootstrap/default.lua` then injects the merged result via `package.loaded["const"] = const`

See [THREE_LAYER_CONSTANTS.md](THREE_LAYER_CONSTANTS.md) for full spec.

## Stage 1: Hardware Pipeline

**Purpose**: Detect and configure monitors + laptop hardware.

```
sys/hardware/default.lua
  ├── sys/hardware/laptop.lua       ← XF86 media keys, touchpad device
  │     └── sys/hardware/laptop-display.lua
  ├── sys/hardware/monitors.lua     ← monitor layout, resolution, scale
  └── sys/hardware/workspaces.lua   ← workspace → monitor bindings
```

**API used**: `hl.monitor({...})`, `hl.device({...})`, `hl.bind()` for media keys.

## Stage 2: Policy Pipeline

**Purpose**: Load swappable strategies (colors + animations) via Strategy Pattern.

```
sys/policy/default.lua
  ├── sys/policy/wallust/wallust-hyprland.lua   ← GENERATED by wallust (colors)
  └── sys/policy/animations/default.lua          ← animation preset
        (alternatives: disable, end4, hyde-optimized, hyde-vertical, ml4w-fast)
```

**Strategy Pattern**: Each animation file is an interchangeable algorithm.
Switch by editing `sys/policy/default.lua` to `require("sys.policy.animations.end4")`.

## Stage 3+: sys.X → user.X Pair Pattern

Every system module has a paired user override:

| sys module | user module | API used |
| --- | --- | --- |
| `sys/env` | `user/env` | `hl.env("KEY", "value")` |
| `sys/misc` | `user/misc` | `hl.config({ misc = {...} })` |
| `sys/input` | `user/input` | `hl.config({ input = {...} })` |
| `sys/layout` | `user/layout` | `hl.config({ general = { layout = "dwindle" } })` |
| `sys/decoration` | `user/decoration` | `hl.config({ decoration = {...} })` |
| `sys/render` | `user/render` | `hl.config({ render = {...} })` |
| `sys/startup` | `user/startup` | `hl.on("hyprland.start", fn)` |
| `sys/keybind` | `user/keybind` | `hl.bind(key, action, flags)` |
| `sys/tags` | `user/tags` | `hl.window_rule({ match=..., tag=... })` |
| `sys/rules` | `user/rules` | `hl.window_rule({ effects..., match={tag=...} })` |

**Key principle**: User files run AFTER sys files (later wins). User files
contain only deltas — don't redeclare sys defaults.

## Rule Application Order (Hyprland wiki confirmed)

Hyprland evaluates `hl.window_rule` calls in **source order** (file-by-file as
`require`d, top-to-bottom within each file):

```
1. sys/tags.lua    → windows get tagged (classification)
2. user/tags.lua   → additional tags (extension)
3. sys/rules.lua   → effects applied by tag (behavior)
4. user/rules.lua  → user overrides (later wins on conflicts)
```

See [TAG_SYSTEM.md](../03-Core-Systems/TAG_SYSTEM.md) for the full rule API.

## Lua ↔ Shell Coordination Mechanism (Round 116)

The Lua config and sh scripts share a **Single Source of Truth (SSOT)** via
`.deps_cache.sh` — a shell-sourceable file auto-generated by `sys/const.lua`.

### Flow

```
sys/const.lua (Lua SSOT)
  │
  ├── M.export_to_shell()  ← called by bootstrap/default.lua on startup
  │     │
  │     ▼
  │   .deps_cache.sh (auto-generated, shell-sourceable)
  │     ├── export HYPR_CONFIG_DIR="..."
  │     ├── export HYPR_SCRIPTS_DIR="..."
  │     ├── export HYPR_CACHE_DIR="..."      ← Round 109
  │     ├── export HYPR_WALLPAPER_DIR="..."
  │     ├── export SWAYNC_DIR="..."
  │     ├── export ROFI_DIR="..."
  │     ├── export TERMINAL="kitty"          ← from lib/deps.lua specs
  │     ├── export NOTIFY="notify-send"
  │     ├── export WALLPAPER_CLIENT="awww"   ← Round 110
  │     └── ... (35 tools + all paths)
  │
  └── require("const")  ← Lua modules use this
        │
        ▼
      sys/keybind.lua, sys/startup.lua, sys/decoration.lua, etc.
        │
        │  const.apps.terminal → "kitty"
        │  const.dirs.scripts → "/home/user/.config/hypr/sys/scripts"
        │  const.cache_dir → "/home/user/.cache"
        │
        ▼
      Lua modules use const.* (never hardcoded)

sh scripts
  │
  ├── source lib/common.sh
  │     │
  │     ├── . .deps_cache.sh  (if exists)     ← SSOT from Lua
  │     │   OR
  │     ├── fallback defaults  (if cache missing)
  │     │
  │     └── helper functions (dt_notify, dt_hl_dispatch, etc.)
  │
  └── use $HYPRCTL, $NOTIFY, $HYPR_CACHE_DIR, etc. (never hardcoded)
```

### Key Components

| Component | Role | Location |
| --- | --- | --- |
| `sys/const.lua` | SSOT — defines all paths + DI variables | `sys/const.lua` |
| `M.export_to_shell()` | Generates `.deps_cache.sh` from SSOT | `sys/const.lua:export_to_shell()` |
| `.deps_cache.sh` | Shell-sourceable cache (auto-generated) | `$HYPR_CONFIG_DIR/.deps_cache.sh` |
| `lib/common.sh` | Sources cache + provides helpers + fallback defaults | `sys/scripts/lib/common.sh` |
| `lib/deps.lua` | 35-tool DI manifest (specs) | `lib/deps.lua` |
| `lib/input_config.lua` | Lua-aware parser (sh calls Lua for kb_layout) | `lib/input_config.lua` |
| `lib/cursor.lua` | Pure Lua cursor zoom (replaces sh pipeline) | `lib/cursor.lua` |
| `dt_hl_dispatch()` | sh→Lua bridge (calls `hyprctl eval "hl.dispatch(...)"`) | `lib/common.sh` |

### Round 107-110 Improvements

- **Round 107**: Added `dt_hl_dispatch()` + `dt_hyprctl_json()` helpers for sh→Lua bridge
- **Round 107**: Migrated cursor zoom from sh pipeline to pure Lua (`lib/cursor.lua`)
- **Round 107**: Added `hyprland.shutdown` handler for daemon cleanup
- **Round 108**: Expanded `lib/deps.lua` from 26 to 35 tools (all DI'd)
- **Round 109**: Added `cache_dir` to SSOT (XDG-aware via `$XDG_CACHE_HOME`)
- **Round 110**: Added `wallpaper_client` DI spec (eliminated hardcoded `awww`)

### Design Principles

- **SSOT**: `sys/const.lua` is the single source; `.deps_cache.sh` is auto-generated
- **DI**: All 35 tools declared in `lib/deps.lua`; scripts use `$TOOL` variables
- **Resilience**: `lib/common.sh` has fallback defaults if `.deps_cache.sh` missing
- **XDG-aware**: `config_hypr` + `cache_dir` + `external` all use XDG env vars

## Design Principles Applied

| Principle | Application |
| --- | --- |
| **Pipeline** | Sequential `require()` chain = compilation phases |
| **Layered Architecture** | bootstrap → sys → user, clear boundaries |
| **Incremental Override** | user/X.lua contains only deltas |
| **Dependency Inversion** | Constants in the `const` module (injected via `package.loaded`), not hard-coded |
| **Single Responsibility** | Each file has one purpose (env/input/decoration/...) |
| **Open/Closed** | sys/ closed; user/ open for extension |
| **Strategy Pattern** | Policy layer swaps algorithms without reload |
